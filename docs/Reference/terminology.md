# Cortex Terminology

Normative definitions for the vocabulary used throughout the Cortex docs. When a term appears in an
architecture chapter, spec, or research note, this page is where it is defined. Summaries in
[`glossary.md`](../glossary.md) are informal; this page is canonical.

Short rule for reading the docs:

```text
.wire source → Wire parser → Circuit → Graph topology → Pulse execution
```

Each layer owns a specific set of terms. This page groups them by layer.

## Substrate layers

**Cortex** is the upstream, consumer-neutral runtime substrate and library surface. It spans the
Algebra, Wire, Circuit, Pulse, and Capability layers as a single product-neutral stack (`.wire`
source → Wire parser → Circuit → Graph topology → Pulse execution). Cortex modules stay
consumer-neutral; domain authority and product policy (launch fields, report sections, model-policy
choices, user-facing labels) live in downstream consumers such as Logos, not in Cortex.

| Term                           | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                           | Owner                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| **Algebra** (a.k.a. **Graph**) | The lowest pure layer of graph and relation laws: vertices, edges, `Empty`, `Overlay`, `Connect`, relation construction, and DAG validation. Pure; no evaluation semantics. `Graph` denotes the topology type within it (`Cortex.Algebra.Graph`).                                                                                                                                                                                                    | `Cortex.Algebra`                                          |
| **Circuit**                    | The validated executable topology. Predeclared nodes plus compatible-port edges, ready for execution. A Wire source file compiles to a Circuit. There is no top-level `Cortex.Circuit` module.                                                                                                                                                                                                                                                       | `Cortex.Wire.Circuit` (Pulse view `Cortex.Pulse.Circuit`) |
| **Wire**                       | The source language and file format used to author Circuits. Composes registered authority (nodes and contracts) into a topology. Normative grammar: [grammar.md](Wire/grammar.md).                                                                                                                                                                                                                                                                  | `Cortex.Wire`                                             |
| **Pulse**                      | The durable runtime that schedules and executes a compiled Circuit. Standalone service `cortex-pulse`.                                                                                                                                                                                                                                                                                                                                               | `Cortex.Pulse`                                            |
| **Capability**                 | The substrate layer that registers executor authority and exposes native pure-executor surfaces to execution; it grants registered authority to Pulse.                                                                                                                                                                                                                                                                                               | `Cortex.Capability`                                       |
| **Linear port graph**          | The typed IR seam between Wire source and pure Graph. Records what pure Graph forgets: node identities, input/output port instances, the exposed input/output frontier, one-use port-edge matches, and the `PortLinear` invariant (no endpoint port consumed by more than one match). Forgetfully lowers to Graph; its runtime projection is the **actualized port graph**. Proof-side home of `PortLinear` (theory/Cortex/Wire/PortLinearity.lean). | `Cortex.Wire` → `Cortex.Algebra` (`LinearPortGraph`)      |

## Wire language

### Core forms

| Term                             | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Contract**                     | A named typed interface that flows through a port. Ambient in a global namespace. Carries a payload kind. Nominal identity: two contracts are equal iff their names are equal.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Node**                         | An explicit graph vertex with typed input/output ports and an implementation body. Has identity; reused references are the same node.                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Port**                         | A slot on a node, typed by a contract. Input (`<-`) or output (`->`). May be labeled.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Port key**                     | The identity tuple `(direction, contract, label)` that `=>` matches on. Absent-label is a distinct key, not a wildcard.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Label**                        | Part of a port's identity for routing, not a decoration. Labeled ports match only identically-labeled partners.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Sum group**                    | Output port form `-> A \| B` with mutual-exclusion metadata: exactly one variant fires per evaluation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Configured executor value**    | Staged value `@executor { config }` with no ports or graph identity. `let`-bindable and executable only through an explicit node body.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Wire value**                   | Any graph-kind (graph) value: a node, a bound form application, a bound `make(...)`/`makeEach(...)` expansion, a composed graph expression, or the empty wire `()`. See [grammar.md §3](Wire/grammar.md).                                                                                                                                                                                                                                                                                                                                                                                          |
| **Port-boundary**                | A wire's unconnected input and output ports. The surface `=>` operates on.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Frontier** (Wire)              | The multiset of named, contract-typed port instances a wire exposes on its boundary — the formal name for the port-boundary, and the object the `FrontierTyped` judgment ranges over (theory/Cortex/Wire/FrontierTyping.lean). Distinct from the Pulse **scheduling frontier** below.                                                                                                                                                                                                                                                                                                              |
| **Endpoint** / **port instance** | A concrete occurrence of a port on a specific node in a wire — one output instance or one input instance. The unit that `=>` matches and that linearity ranges over: each endpoint is consumed by at most one match. Distinct from **Port** (the declared typed slot): a reused or generated node yields fresh port instances. Proof-side: `SourcePortInstance` / `ActualizedPortInstance` (theory/Cortex/Wire/PortLinearity.lean).                                                                                                                                                                |
| **Edge**                         | Layer-relative. Typed layer: not an object but the **saturation event** — one output endpoint matched against one input endpoint by `=>` under the linear side-conditions; all typed content lives in the two endpoints. Algebra layer: a bare ordered vertex pair — forgetful lowering discards port identity, polarity, labels, and contracts, keeping only source→target order; the Mokhov laws hold only past that point, so kinds or other decoration on the algebra-layer edge are ruled out. ADR 0087.                                                                                      |
| **Saturation** (Wire)            | The match predicate `=>` applies: an output endpoint saturates an input endpoint when their port keys agree and each side is consumed exactly once (`hMatchedFunctional`/`hMatchedInjective`, theory/Cortex/Wire/FrontierTyping.lean). A successful application is an edge (typed layer). Distinct from Pulse **scheduler pool saturation** (ADR 0068) and from the rejected block-level `saturate` directive (ADR 0086). ADR 0087.                                                                                                                                                                |
| **Port role** (designed)         | The parametrization of an endpoint for matching purposes: `(polarity, contract, label, multiplicity, relation family, protocol state)`. Today's Wire is the degenerate instance — family `{value}`, multiplicity `{linear}`, trivial protocol, nominal compatibility. Non-degenerate instances ("edge kinds") are design-only, bounded by ADR 0085's partition-or-grade rule. ADR 0087.                                                                                                                                                                                                            |
| **CorePure**                     | The deterministic expression language used by output equations and executor input arguments. No IO, imports, recursion, host callbacks, model/tool calls, time, or randomness; evaluates against a closed builtin environment when the referenced input ports are available. Full normative spec: [grammar.md §8](Wire/grammar.md).                                                                                                                                                                                                                                                                |
| **Latent branch**                | Wire's mechanism for closed-world conditional branching without turning possibilities into live topology. A conditional lowers to one owner/anchor node that stays in the live compiled graph plus one or more sealed latent branch fragments (or implicit pass-through continuations); exactly one continuation is selected and materialized while all others remain latent and ineligible under ordinary readiness rules. The anchor stays visible for provenance/lineage. Full semantics: [conditionality.md §7](Wire/conditionality.md); ADR 0007 (lowering); ADR 0036 (selected-cost budget). |

### Composition algebra

| Term                           | Definition                                                                                                                                                                                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`<>` overlay**               | Set union of nodes and edges across two wires. The primitive of the algebra.                                                                                                                                                                                                           |
| **`=>` connect**               | Linear boundary contraction: each compatible output/input endpoint pair is consumed at most once; no implicit copy or aggregation.                                                                                                                                                     |
| **Mokhov algebra**             | The algebraic basis for Wire's graph expressions: `Empty \| Vertex \| Overlay \| Connect` per Mokhov's _Algebraic Graphs with Class_. Fixed at four constructors; Cortex does not extend it ([03-formalism-stack.md](../Architecture/03-formalism-stack.md)).                          |
| **`*` finite-product adapter** | Inserts an explicit finite-product adapter node between its operands, folding/unfolding record fields or a bounded indexed contract `[T; N]` by label. Not an exception to `=>`: both sides connect by ordinary linear endpoint matching ([grammar.md §7](Wire/grammar.md); ADR 0052). |

### Compile-time abstraction forms (Axis 2)

These are hygienic compile-time macros, not type-system constructs: they expand to ordinary typed
nodes/graph values **before** graph lowering, and the executable kernel rejects them unexpanded
(`ElabError.unsupportedForm`, theory/Cortex/Wire/GraphElaborationExec.lean). Full grammar:
[grammar.md](Wire/grammar.md).

| Term                    | Definition                                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`kind`**              | A compile-time node-body abstraction. A kind application expands to exactly one ordinary node declaration. ADR 0045; grammar.md §5.                                                 |
| **`form`**              | A compile-time graph abstraction. A bound form application expands to a multi-node graph value. Non-recursive in v1; must be `let`-bound. ADR 0046; grammar.md §5.                  |
| **`make` / `makeEach`** | Bounded compile-time node generation: `make(N, K)` expands to N nodes; `makeEach(items, K)` expands to a per-item fan. ADRs 0048 / 0051; grammar.md §5.                             |
| **`select`**            | Additive-choice / guarded-affine collapse over an exclusive set of latent branches; actualizes exactly one already-admitted arm. ADR 0033; theory/Cortex/Wire/SelectAdmission.lean. |

### Value operators

| Term                     | Definition                                                                                                                                                                                                                                                                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`//` merge**           | Right-biased shallow record merge.                                                                                                                                                                                                                                                                                                                   |
| **`++` concat**          | String and list concatenation. **Unreconciled:** `grammar.md` defines no `++` operator — its CorePure operator inventory (§8) omits it and concatenation is the `concat` builtin (§8). Pending reconciliation, either drop `++` here or add it to the grammar as authored surface sugar for `concat`. Not surfaced in the glossary until reconciled. |
| **`\|` sum constructor** | Output-port mutual-exclusion form; distinct grammar construct, not pure sugar.                                                                                                                                                                                                                                                                       |
| **`@` application**      | Executor authority plus config: `@qualified.name { ... }`. Produces a configured executor value.                                                                                                                                                                                                                                                     |

### File-level forms

| Term                       | Definition                                                                                                                                                |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **File-return expression** | A `.wire` file's last expression without trailing `;`. Becomes the file's value. A file is a wire iff it has a file-return.                               |
| **Declaration-only file**  | A file without a file-return expression. Contributes ambient contracts and importable `let` bindings; nothing else.                                       |
| **Program**                | A root `.wire` file plus the transitive closure of its imports. The unit over which ambient contract collection and cross-file reference resolution runs. |

### Frontier-flow reading (ADR 0047)

| Term                          | Definition                                                                                                                                                                  |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Frontier transformer**      | A Wire source expression read as a function from an input frontier to an output frontier; composition transforms frontiers rather than wiring a fixed graph. See ADR 0047.  |
| **Carried endpoint**          | A frontier endpoint that crosses a `=>` composition unmatched and remains exposed on the composed frontier (an identity wire for an open boundary). See ADR 0047.           |
| **Stage-structured pipeline** | The reading where `<>` forms a same-stage frontier (stage formation) and `=>` advances to the next stage (stage advancement); the basis for the ADR 0047 precedence ladder. |

## Executors and registry

| Term                                        | Definition                                                                                                                                                           |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Executor**                                | A registered external recipe for turning a node's inputs into outputs. Referenced by `@qualified.name`. LLM call, pure transform, shell-out, or subgraph evaluation. |
| **Executor alphabet**                       | The globally-ambient set of registered executor names. Closed: user code cannot define new executors, only compose them.                                             |
| **Vocabulary** (of an executor)             | The set of contract names the executor can produce or consume.                                                                                                       |
| **Structural constraints** (of an executor) | The rules a node's port signature must satisfy to apply the executor.                                                                                                |
| **Purity class**                            | `pure` or `impure`. Informational; does not affect static type-checking.                                                                                             |
| **Executor projection**                     | The registered typed port boundary or structural constraint checked against an authored node body.                                                                   |
| **Port-polymorphic executor**               | An executor whose accepted port signature has degrees of freedom. The authored node boundary supplies the concrete shape.                                            |
| **Tool registry**                           | A sibling ambient namespace to the executor alphabet. Holds named tool values (`getDate`, `searchAssets`, …) referenced inside config records.                       |
| **Config constructor**                      | A tagged-record value form inside a config: `qualified.name { ... }` (no leading `@`). Semantics determined by the consuming executor's schema.                      |

## Runtime vocabulary

| Term                                        | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Envelope**                                | The JSON-carrier shape every Wire value travels in at runtime: `{ contract, port, payloadKind, mediaType, producer, value, provenance }`. Code: `WireValue` (src/Cortex/Wire/Value.hs).                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Payload kind**                            | A contract's runtime category: `json`, `markdown`, `text`, `table`, `artifact_ref`. Selects validation and rendering.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Contract registry**                       | The Haskell-owned authoritative definitions of contracts: schema, codec, payload kind, examples, lint rules.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Evaluation-boundary check**               | The runnable-wire gate: every singular input connected to exactly one edge. Runs at evaluation-preparation, not type-checking.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Rewrite** (a.k.a. rewire)                 | A bounded runtime topology modification over a live Circuit. Subject to vocabulary, endpoint-compatibility, topology, and resource (gas) bounds. Module: `Cortex.Pulse.Rewrite` plus the Wire compiler.                                                                                                                                                                                                                                                                                                                                                                                                |
| **Realized circuit**                        | The concrete Circuit topology in effect after admitted rewrites during a run. Same concept as **Materialized graph** (plan graph plus all admitted rewrites); reconciled to a single canonical entry — see **Materialized graph**. A runtime artifact, not a grammar construct.                                                                                                                                                                                                                                                                                                                        |
| **Gas**                                     | The structural-change budget consumed by rewrites: nodes added, edges added, depth, frontier breadth, rewrite operations.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Proof contract**                          | A mechanized safety surface whose terms lead runtime implementation. Haskell admission code must either construct values satisfying the proof contract or reject the input before it reaches that boundary.                                                                                                                                                                                                                                                                                                                                                                                            |
| **Topological memory**                      | A node-addressable accumulated context from upstream evaluations. Declared on the node, consumed at evaluation time. Downstream home: `Logos.Memory.Topological`; Pulse supplies the settled event state.                                                                                                                                                                                                                                                                                                                                                                                              |
| **Scheduling frontier** (Pulse)             | The set of graph nodes ready to execute at a given point. Pulse schedules over it. Distinct from the Wire **Frontier** (port-boundary multiset) above.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Artifact reference** (`artifact_ref`)     | A runtime value carried under the `artifact_ref` payload kind: a JSON object that references a durable artifact owned by a consumer or host boundary instead of inlining its bytes. Media type `application/vnd.cortex.artifact-ref+json`. Code: `WirePayloadArtifactRef` (src/Cortex/Wire/Value.hs).                                                                                                                                                                                                                                                                                                  |
| **Provenance**                              | The runtime record of where a value came from: the optional `provenance` field on an Envelope. Value-level provenance (which executor/run produced the value) is owned by Architecture/08; structural-event provenance (rewrite proposals and admission decisions) is the separate **Rewrite log** of Architecture/07. Code: `wireValueProvenance` (src/Cortex/Wire/Value.hs).                                                                                                                                                                                                                         |
| **Compiled circuit node**                   | The structural classification of vertices in a compiled Circuit, and the only node-classification axis: **task** (executor-backed work), **signal boundary** (awaits a named external signal), **artifact boundary** (emits a durable artifact; ADR 0071), **rewrite boundary** (scoped structural rewrite authority), and **condition** (latent-branch anchor; ADR 0007). Executor identity, typed ports, and registered binding metadata carry all task-node semantics; there is no separate semantic node-kind field (ADR 0024). Code: `CompiledCircuitNode` (src/Cortex/Wire/Circuit/Compiled.hs). |
| **Plan graph**                              | The initial Circuit compiled from Wire source, before any admitted rewrites; the base that the materialized graph extends. Architecture/07.                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Materialized graph**                      | The concrete graph topology in effect during a run: the plan graph plus all admitted rewrites materialized up to the current watermark. The runtime artifact rewrites and resume operate over; resume reconstructs it only through the watermark, finishing any admitted-but-unmaterialized lineage first. Also called the **Realized circuit**. Architecture/07.                                                                                                                                                                                                                                      |
| **Rewrite log**                             | The append-only provenance of rewrite proposals and admission decisions. Each entry carries the accepted rewrite specification, the anchor output needed to replay into inserted entry nodes, the static cost, and a monotone rewrite id. Rejected proposals are retained as audit rows, not silently discarded. Architecture/07.                                                                                                                                                                                                                                                                      |
| **Watermark**                               | The monotone rewrite id up to which admitted rewrites have been materialized into durable graph state. Advances atomically with the node-state and budget changes it implies; resume reconstructs the materialized graph only through the watermark and deterministically finishes any admitted-but-unmaterialized lineage before scheduling. Architecture/07.                                                                                                                                                                                                                                         |
| **Anchor**                                  | The existing node a rewrite attaches to. `ExpandNode` replaces the anchor with a subgraph; `AppendAfter` retains it and feeds its output into the inserted subgraph as continuation input. Architecture/07; ADRs 0005, 0032.                                                                                                                                                                                                                                                                                                                                                                           |
| **Rewrite slot**                            | Exclusive (linear) authority to transform a boundary at an anchor in one planning epoch; spent at most once per epoch. The linear resource each admitted rewrite consumes at its anchor (per-epoch rewrite-slot uniqueness is a Lean theorem target). ADRs 0032, 0038.                                                                                                                                                                                                                                                                                                                                 |
| **Boundary law**                            | The explicit rule a rewrite class obeys at a boundary — contract-preserving substitution, append continuation, or conditional branch actualization. Boundary laws stay conceptually distinct even when v1 realizes several through the same `GraphRewrite` constructor, because each consumes different boundary resources. Architecture/07; ADRs 0028, 0032.                                                                                                                                                                                                                                          |
| **Materialization**                         | The durable installation of admitted rewrites: node-state changes, budget consumption, and watermark advance applied in one atomic commit. Distinct from admission, which only accepts a proposal — admitted lineage may exist beyond the watermark ("admitted but not yet applied"). Architecture/07.                                                                                                                                                                                                                                                                                                 |
| **Admit** / **admission**                   | Runtime acceptance of a proposed rewrite after every admission check passes: vocabulary bounds, endpoint compatibility, topology validity, resource (gas) bounds, and runtime policy. Stages and planners propose; only the runtime admits and mutates durable graph state. Distinct from the proof-side judgment **`Admits`** (the certifying elaborator's acceptance of a core graph expression). Architecture/07.                                                                                                                                                                                   |
| **Selected-cost**                           | The current gas policy for latent branches: a compiled branch family is validated as a closed set, but unselected arms neither prepay nor consume runtime rewrite budget; only the selected arm spends ordinary rewrite budget when actualized. Named design debt — weaker than a reserved-capacity policy, so Cortex does not yet guarantee every compiled arm can still materialize after unrelated rewrites spend the budget. Architecture/07; ADR 0057.                                                                                                                                            |
| **Run**                                     | The unit of durable execution identity in Pulse: a single execution with a `run_id`, optional `parent_run_id` lineage, a checkpoint lineage, and a lifecycle status. Checkpoints belong to a run; Resume continues the same run, Retry starts a fresh one linked via `parent_run_id`, and a managed-facade caller can declare a successor run linked the same way (`ManagedRunOptions`). Architecture/06.                                                                                                                                                                                              |
| **Stage** (Pulse)                           | A single admitted transition in a Circuit's stage plan — the unit Pulse drives forward, one transition at a time. Each stage carries a stable typed identity (`NodeId`, `stageId`, `StageTemplateId`, `StageActionId`), a replay-safety class, and optional per-stage timeout/retry policy. Distinct from the Wire **Stage-structured pipeline** reading of `<>`/`=>`. Architecture/06.                                                                                                                                                                                                                |
| **Checkpoint**                              | Persisted run state at a stage boundary, stored as a versioned `CheckpointEnvelope`. In the durable profile the executor rejects any stage transition that does not include a checkpoint write, so every stage boundary is recoverable; surfaces reading checkpoint payloads validate envelope format, task type/version, runtime version, and checkpoint name first. Architecture/06.                                                                                                                                                                                                                 |
| **Lease**                                   | A scheduler ownership claim over a run (`runs.lease_owner`, `runs.lease_expires_at`). Only the holder advances the run; the owner renews mid-flight, and stale leases are reclaimed on startup (`reclaimOwnedRuns` refreshes own leases for resume, `recoverExpiredRuns` fails out abandoned ones). Architecture/06; ADR 0068.                                                                                                                                                                                                                                                                         |
| **Ephemeral / Durable profile**             | Pulse's two execution profiles over one transition model. **Ephemeral**: in-process memory, no durable event log or checkpoint lineage after exit; still enforces topology validation, port linearity, executor authority, and rewrite admission. **Durable**: adds persisted events, checkpoints, resume, provenance, observability, lease recovery, and rewrite materialization. Architecture/06.                                                                                                                                                                                                    |
| **Replay**                                  | Deterministic re-execution over the journaled durable prefix of a run. Each stage declares its replay safety — `SafeToReplay` or `Irreversible`; the executor warns when an `Irreversible` stage shows a prior stage-log entry during resume, since its side effect may have partially completed. Architecture/06.                                                                                                                                                                                                                                                                                     |
| **Compatibility witness**                   | A fingerprint carried on a compiled Circuit that lets durable state key against the artifact it may resume: a family string plus a SHA-256 digest over the serialized compiler input for that artifact family. Not a proof of semantic equivalence and not host authority — a check that an artifact belongs to the expected circuit family and digest lineage before it is treated as reusable. Code: `CircuitCompatibilityWitness` on `CompiledCircuit` (src/Cortex/Wire/Circuit/Compiled.hs). Architecture/04; ADR 0006. Distinct from the runtime-resume **Compatibility barrier**.                |
| **Compatibility barrier**                   | An explicit runtime barrier on checkpoint resume: version and shape mismatches are classified as typed compatibility failures rather than resumed silently, and the default recovery across version drift is a fresh run that preserves operator intent and parent provenance. ADR 0011. Distinct from the compiled-artifact **Compatibility witness** (ADR 0006).                                                                                                                                                                                                                                     |
| **Settled state** / **settled-state query** | Completed upstream Pulse run state exposed as a deterministic query surface: the **Past** graph of settled nodes (`NodeCompleted`, `NodeSkipped`, `NodeRewritten`) with materialized outputs. Memory is a query over this substrate, not a separate store; running/waiting (**Present**) and not-yet-materialized (**Future**) nodes are excluded by construction. Topological memory consumes it via `queryMemory`. Architecture/06.                                                                                                                                                                  |
| **Actualized port graph**                   | The runtime concrete port-instance view of the materialized Circuit or Pulse state — the same shape as the source-side **Linear port graph**, now actualized. The projection where source frontier linearity connects to runtime well-formedness for the proof track. Architecture/04.                                                                                                                                                                                                                                                                                                                 |

## Ownership boundary

- **Wire composes registered authority.** Wire source references registered nodes, contract IDs,
  executor config, and wiring. It does not invent executors, tools, payload types, or domain
  authority.
- **Theory names safety obligations.** Where a mechanized proof contract exists, the proof-side
  vocabulary is normative. Runtime code enforces that shape at admission and persistence boundaries;
  it does not weaken the contract to fit convenient implementation types.
- **Haskell owns what the authority means.** Executors, contracts, codecs, payload kinds, and
  registry schemas are Haskell-defined and live outside Wire.
- **Product concepts stay downstream.** Launch fields, report sections, model-policy choices,
  user-facing workflow labels — these live in consumer bindings. They can wrap a Circuit; they are
  not part of the generic Cortex Circuit layer.

### Proof-side vocabulary

Mechanized terms from the Lean theory tree. Status of each is tracked in
[proof-status.md](proof-status.md); these glosses are orientation only.

| Term                              | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`Admits`**                      | Inductive judgment that the certifying elaborator accepts a core graph expression. Five constructors: empty, node, binding, overlay, connect (theory/Cortex/Wire/GraphElaboration.lean).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **`FrontierTyped`**               | The four-place frontier-typing judgment `FrontierTyped mod expr outputs inputs`; the mechanized port discipline. Reached only via `frontierTyped_of_admits` (theory/Cortex/Wire/FrontierTyping.lean).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **`CertifiedGraph`**              | A graph object bundled with its `Admits` proof, produced by the certifying elaborator (theory/Cortex/Wire/GraphElaborationExec.lean).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **`AdmissionArtifact` / `Sound`** | The serialized admission artifact and its `Sound` proposition (schema/linearity + primitive/generated/select/phantom soundness). `Sound` reconstructs to the artifact-boundary `PrimitiveGraphReconstruction`, **not** to `CertifiedGraph`/`FrontierTyped` (theory/Cortex/Wire/AdmissionArtifact/Sound.lean, PrimitiveReconstruction.lean:330-335).                                                                                                                                                                                                                                                                                                                                                                         |
| **Admission witness**             | A proof-shaped evidence record attached at a rewrite or select admission boundary, carrying the obligations admission must discharge (e.g. `BudgetedBoundaryResourceUse`, theory/Cortex/Wire/BoundaryResource.lean; per-key port-use accounting). The schema-versioned Haskell-to-Lean exchange form is fixed by ADR 0079 (Wire admission artifact as proof-witness exchange contract); ADR 0081 requires the select admission witness from ADR 0033 to distinguish guarded-affine branch-local endpoint uses. Predecessor hashes, rewrite admission witnesses, and budget annotations attach to the persisted record (ADR 0021). Distinct from the broader **`AdmissionArtifact`** (the serialized witness exchange form). |

[Architecture/02-ownership-and-boundaries.md](../Architecture/02-ownership-and-boundaries.md) for
the full ownership story.

in [taxonomy.md](../taxonomy.md). These compact entries are the canonical superset reference for the
names used across the docs.

| Term                        | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Logos library**           | The downstream structured reasoning library built on the Cortex substrate. It names reusable LLM-shaped catalogs — `Logos.Archetypes`, `Logos.Thought`, `Logos.Memory`, `Logos.Patterns` — together with provider/model adapters, `.wire` templates, prompt families, and artifact IRs. It composes substrate mechanics (Algebra, Wire, Pulse, Capability, runtime provenance) into reusable reasoning programs; it does NOT extend the runtime alphabet, register executor kinds, or own the contract-registry surface. Dependency direction is strict: substrate code must not import Logos; Logos may import runtime types and publish opt-in catalog values or source templates. Deep home: Consumers/Logos/reasoning-library.md. |
| **Logos.Archetypes**        | The canonical catalog within the Logos library that classifies reusable modes of cognition. The first catalog contains seven archetypes — Logos, Sophia, Techne, Episteme, Kritikos, Themis, Poiesis — each a semantic definition of a cognitive mode, not a provider/model/prompt/tool/ontology choice. Those concrete choices belong to activation bundles (`Logos.Archetypes.<Archetype>.Activation`) or downstream bindings. Catalog membership grants no executor authority and creates no runtime registry.                                                                                                                                                                                                                     |
| **Logos archetype**         | The `Logos.Archetypes.Logos` archetype: the cognitive mode of discursive reason, argument, and symbolic reasoning — making reasoning explicit as structured claims, premises, inference, and explanation. One member of the `Logos.Archetypes` catalog. It is NOT the Logos library or the `Logos` namespace of the same name; the name collision is intentional but the two are distinct — the library is the container, this archetype is one entry inside `Logos.Archetypes`.                                                                                                                                                                                                                                                      |
| **Logos activation bundle** | The operational implementation of an archetype, homed at `Logos.Archetypes.<Archetype>.Activation`: the concrete bundle of prompt discipline, retrieval corpus, embedding index, tool surface, evaluation criteria, memory policy, and runtime contract that makes the archetype's semantic definition runnable. The archetype is the definition; the activation is the assets and policies implementing it. A thought frame composes one or more activations into a single evaluation.                                                                                                                                                                                                                                               |
| **Logos.Thought**           | One bounded model-mediated cognitive evaluation bound to a graph node. A thought frame composes one or more archetype activations into a single evaluation. It is not a durable persona or standing agent: identity belongs to the node, and the thought is the act of evaluating it under the active activation(s).                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Logos.Memory**            | The Logos subsystem that owns cognitive context construction: retrieval, ranking, packing, compaction, source selection, topological context, and memory tools, all driven through substrate state and APIs rather than new runtime authority. `Logos.Memory.Topological` is the downstream home of the substrate's **Topological memory**; Pulse supplies the settled event state that it reads.                                                                                                                                                                                                                                                                                                                                     |
| **Logos.Patterns**          | The Logos catalog of reusable reasoning programs — library-owned `Logos.Patterns.<Name>` modules interpreted by existing substrate APIs, not new runtime kinds. `Logos.Patterns.DeepReport` is the planned extraction target for reusable deep-report reasoning: its contracts, ports, `.wire` templates, prompts, memory presets, and evaluation policy.                                                                                                                                                                                                                                                                                                                                                                             |
